# Open questions

These are the open directions from the v0.1 design note, plus one labeling question created by this planting. They are not findings.

## Q-0001 — What fields does the first card need?

- **Difficulty:** D2
- **Need:** chief-of-staff practice, data minimization
- **Question:** Which Card, Claim, and Evidence fields are enough to support one thank-you or pre-meet brief, using the design note's card contents (preferred mail, phone, email, org ties, how we know them, next courtesy) plus source, as-of date, and grade?
- **Evidence wanted:** A field list short enough that P-10 still holds, with each contact field required to carry a source and a grade. A sample using a real person is out of scope until Jacob asks.

## Q-0002 — Where do living cards sit first?

- **Difficulty:** D2
- **Need:** Notion use, or a file store
- **Question:** The design note says Notion holds joint command notes and needs a Human Log database or page pattern. Is the first living store that database, a page pattern, or files inside this Seed?
- **Evidence wanted:** An owner choice, and a one-page map of how a stub card is created before a meeting. Creating the database is a separate approval from answering the question.

## Q-0003 — What is the first connector, if any?

- **Difficulty:** D3
- **Need:** calendar and mail workflow, privacy limits
- **Question:** The open connector work is a calendar pre-brief and mail crumbs from meeting and thank-you threads. Which one, if either, should exist before a full courtesy cycle has been done by hand?
- **Evidence wanted:** A single trigger definition (for example, a calendar invite that names a new person) and an explicit list of fields that connector may write into Claims, never directly into a Card.

## Q-0004 — What counts as Jacob's OK on grade D?

- **Difficulty:** D1
- **Need:** owner decision
- **Question:** Grade D is an aggregator and needs Jacob's OK, and an aggregator is never promoted alone. What recorded act counts as that OK, and where is it stored so a later session can see it?
- **Evidence wanted:** A one-line rule and a place it will be written. Until that exists, grade D stays a lead.

## Q-0005 — What should the separate tools accept?

- **Difficulty:** D3
- **Need:** interface design for the greenlit tools
- **Question:** confidence-grader, cya-log, the entity-card schema, and registry-ladder are separate software the design note says Jacob greenlit. What is the smallest input and output they must share with this Seed (grade, source, as-of, CYA log line, promotion result)?
- **Evidence wanted:** A short interface note. The tools themselves belong in another repository.

## Q-0006 — Should executability stay E1?

- **Difficulty:** D1
- **Need:** protocol judgment
- **Question:** Planting declared executability E1. Agency also allows autonomous research on public lawful sources, which is close to the protocol's E2 description. Should a later decision move this Seed to E2 only after a bounded research procedure is written, and leave E1 in place until then?
- **Evidence wanted:** An owner decision. This planting does not make that move.
