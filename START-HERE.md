## The shortest explanation

A Seed is a portable package of intent, knowledge, uncertainty, history, and next questions. It should let an unfamiliar human or capable agent become useful without needing the original conversation or creator.

This repository is **Seed S-0000**, the Golden Seed. It defines Seed Protocol while using the protocol to describe itself.

```text
human idea
    ↓
structured Seed
    ↓
humans + agents investigate, challenge, and test it
    ↓
evidence changes the Seed
    ↓
the idea can sleep, fork, fail, or continue without its creator
```

## What is true today

- The doctrine is developed enough to test.
- The protocol is an experimental `0.1-draft`, not a standard.
- The local reference tools and seven structural tests work.
- Cross-domain usefulness and independent agent bootability remain unvalidated.
- Seed Commons is a possible future platform, not a product that exists today.

## A safe first contribution

You do not need to join a team. Pick one path:

1. Read the [60-second explanation](docs/SEED-IN-60-SECONDS.md) and report what remains confusing.
2. Choose a [D1 or D2 Quest](docs/FIND-A-QUEST.md).
3. Compare this idea with prior work you know.
4. [Attack one assumption](docs/ATTACK-THE-SEED.md).
5. Ask a question in GitHub Discussions without editing any file.

The project values useful correction more than agreement. If the protocol is unnecessary, too complicated, or built on the wrong categories, evidence of that is a successful contribution.

## One rule before you continue

Do not confuse polish with proof. A well-written Seed can still be wrong, and a structurally valid folder does not contain validated knowledge.
