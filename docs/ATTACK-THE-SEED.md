# Attack the Seed

Seed Protocol assumes it is wrong in ways it cannot yet perceive. A useful attack is not vandalism or performative disagreement. It identifies a claim, shows why the weakness matters, and gives the project a way to learn.

## What can be attacked?

- a principle that fails under real conditions;
- a hidden assumption;
- evidence that does not support the claim;
- a Decision whose reversal conditions have arrived;
- an incentive people or agents will game;
- an externality the model ignores;
- a category that frames the problem incorrectly;
- the central thesis that a portable Seed is useful at all.

## The attack loop

```text
TARGET → CLAIM → CONSEQUENCE → EVIDENCE → TEST → POSSIBLE RESOLUTION
```

A strong Challenge answers:

1. What exact object or claim are you attacking?
2. What is wrong, missing, or dangerously framed?
3. Why would the project care if you are right?
4. What evidence exists now?
5. What observation or experiment could change confidence?
6. Should the claim be retained, revised, branched, or retired?

## Four useful modes

| Mode | Question |
|---|---|
| Skeptic | What claim lacks adequate support? |
| Red team | How could this fail catastrophically or systemically? |
| Incentives critic | How will participants game or corrupt this mechanism? |
| Alien | Are the project’s categories themselves wrong? |

## Current attack surface

See [`challenges/README.md`](../challenges/README.md) for the live index. Foundational open attacks already question whether:

- a universal Seed object is too general;
- the structure overwhelms spontaneous idea capture;
- motivation mechanics corrupt purpose;
- distillation erases the human meaning it is meant to preserve.

The broader model boundary identifies weak coverage of ownership, privacy, culture, governance, security, safety, accessibility, incentives, and tacit knowledge.

## How to contribute an attack

- **No Git experience:** open a GitHub Discussion and explain the concern in ordinary language.
- **Structured proposal:** use the Challenge issue form.
- **Repository contribution:** copy the pattern in an existing `C-####` file and open a pull request.
- **Evidence:** link a primary source, counterexample, measurement, or reproducible observation.

The project should reward a correction that destroys a bad idea more than prose that makes the bad idea sound impressive.

## Guardrails

Attack claims, systems, incentives, and assumptions—not contributors. State uncertainty. Do not manufacture evidence. Do not expose private information. Physical or high-consequence testing requires authority beyond what this repository grants.
