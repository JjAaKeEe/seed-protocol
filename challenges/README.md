## Attack categories

- **Evidence:** the support is missing, weak, indirect, or contradicted.
- **Assumption:** an unstated premise fails under important conditions.
- **System:** the whole design fails through interaction or scale.
- **Incentives:** participants will game or corrupt the mechanism.
- **Externality:** costs fall outside the model.
- **Safety:** the design enables unacceptable harm or authority confusion.
- **Ontology:** the categories used to define the problem are wrong.
- **Replacement:** another model solves the need more simply.

## Open a Challenge

Use the GitHub Challenge issue form for an early structured attack. Create a `C-####` file when the objection is sufficiently specific and durable.

A Challenge should identify:

1. target;
2. claim;
3. consequence if correct;
4. current evidence;
5. proposed test or observation;
6. possible resolution;
7. status.

Challenges are preserved when resolved. The point is not to build an archive of conflict; it is to stop the Seed from forgetting what reality taught it.

See [Attack the Seed](../docs/ATTACK-THE-SEED.md) for examples, contribution routes, and guardrails.
